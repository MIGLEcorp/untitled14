# MBrowser: управление RAM, VRAM и SSD

## Настройки

Откройте **☰ → Память и GPU**. Настройки сохраняются в
`%LOCALAPPDATA%\FeatherBrowser\preferences.json`.

- **Performance:** Chromium оставляет фоновые страницы живыми. Нет автоматического
  освобождения WebView2; максимальная отзывчивость при переключении.
- **Balanced:** неактивные безопасные вкладки выгружаются после выбранного
  времени простоя (изначально пять минут); ориентировочный предел 12 живых
  WebView2, выгрузка при низкой доступной RAM.
- **Low Memory:** период простоя не более четырёх минут, ориентировочный
  предел пять живых WebView2; реагирует на низкий объём свободной RAM.
- **Extreme:** период не более двух минут, ориентировочный предел два
  живых WebView2; вкладки восстанавливаются с URL по мере использования.

Пределы не жёсткие: защищённые вкладки остаются в памяти. Время между
переключением на вкладку и выгрузкой ограничивается гистерезисом.

**Автоматическая выгрузка** управляется отдельной галочкой. Изменение режима
действует сразу. Дополнительный переключатель **GPU-ускорение Chromium
(использовать VRAM)** действует после перезапуска приложения.
С включённым переключателем Chromium сам управляет GPU и VRAM; отключение
задаёт поддерживаемый Chromium `--disable-gpu`, переходя на программный
рендеринг, который часто потребляет больше CPU. Это **не перенос RAM в VRAM**.

Для сайтов, на которых важна непрерывная работа JavaScript или несохранённых
документов, откройте сайт и включите **Не выгружать автоматически: [домен]**
в том же меню.

## Выгрузка и восстановление

Перед уничтожением WebView2 браузер проверяет загрузки, сетевую активность,
проигрывание звука, активные медиаэлементы и признаки изменённых форм.
После прохода проверки сохраняются URL, заголовок, ограниченная история и
прокрутка. Сессия сохраняется атомарно в `session.json` с асинхронной
записью на SSD. Не сериализуются пароли или содержимое форм.

При возвращении вкладки создаётся новый WebView2 в прежнем пользовательском
профиле, страница загружается по URL и восстанавливается позиция прокрутки.
Авторизация, cookie и кеш принадлежат обычному профилю WebView2. Однако
**полное JavaScript/DOM/SPA/WebRTC-состояние восстановить нельзя** через
публичный API. Некоторые непомеченные изменения формы могут не определяться;
для чувствительных сайтов обязательно используйте исключения.

## VRAM и DLL

`Native\MBrowser.GpuDiagnostics.dll` — нативный C++-модуль. Через DXGI 1.4
он показывает **бюджет VRAM вызывающего процесса**, а не всех WebView2.
Отдельный счётчик Windows PDH показывает суммарное использование выделенной
видеопамяти по GPU-адаптерам, когда системные счётчики доступны. Сумма Working Set процессов также
может учитывать общие страницы несколько раз; рядом доступны показатели
Private Bytes. Параметры разных типов памяти не смешиваются.

Выделение DOM-объектов, heap JavaScript или неотображаемых частей сайта
непосредственно в VRAM/SSD потребовало бы переработки Chromium, а не просто DLL.
Глобальное применение `content-visibility: auto` к чужим сайтам способно
сломать их разметку; MBrowser не внедряет такое CSS автоматически.
Графический GPU-рендеринг уже выполняется внутри Chromium.

## Диагностика и тесты

Откройте **☰ → Диагностика RAM / VRAM**: приложение, все процессы WebView2,
доступная RAM, число выгруженных вкладок, размер файла сессии, счётчики
выгрузки и восстановления, системная VRAM (PDH) и бюджет процесса (DXGI).

Проверка:

```powershell
dotnet build .\MBrowser.csproj -c Debug -p:Platform=x64
.\bin\x64\Debug\net10.0-windows\MBrowser.exe --self-test
.\bin\x64\Debug\net10.0-windows\MBrowser.exe --smoke-test
```

Smoke-тесты используют локальный тестовый сервер: они проверяют выгрузку,
создание нового WebView2, восстановление прокрутки и сохранение изменённой
формы в незагруженной вкладке.

Для достоверного сравнения с Chrome/Edge нужно отдельно провести замеры
одинаковых сайтов, числа вкладок и одинакового ожидания после загрузки.
Существующий тестовый прогон **не подтверждает** конкретный процент
уменьшения RAM или VRAM.
