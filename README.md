# Feather

Браузер для Windows x64 на C# / .NET 10 и Windows Forms. Основные вкладки используют системный Microsoft Edge WebView2 (Chromium). Интерфейс на русском, собственная рамка окна, восстановление сессии и отложенная выгрузка фоновых страниц.

## Запуск

Откройте **`start.vbs`** или **`dist\Feather.exe`**: консольное окно не создаётся. `start.cmd` оставлен для запуска из командной строки. При переносе скопируйте всю папку `dist`, включая `Modules` и `Features`, а не только exe.

Нужны [.NET Desktop Runtime 10 x64](https://dotnet.microsoft.com/download/dotnet/10.0) и [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/). Для сборки нужен .NET SDK 10. Экспериментальный WebKit устанавливается отдельно по запросу; подробности — в [ENGINE.md](ENGINE.md).

## Возможности

- До 100 вкладок, поиск из адресной строки, история назад/вперёд, загрузки и восстановление сессии.
- Фоновые вкладки сохраняют живую страницу при переключении и выгружаются после простоя.
- Полноэкранный режим F11, собственные кнопки свернуть/развернуть/закрыть, перетаскивание и изменение размеров окна. При открытии меню и смене фокуса стандартная строка заголовка Windows больше не появляется поверх вкладок.
- Три сохраняемые темы: аниме «Сакура» по умолчанию, тёмная и светлая. В аниме-теме — иллюстрация с двумя взрослыми героинями на главной и их портреты во вкладках, нижней панели и меню. Оформление рисуется Windows Forms без отдельного веб-рендерера или фонового видео.
- Закладки с поиском, импортом и экспортом HTML; пароли WebView2 и отдельное зашифрованное хранилище импортированных паролей.
- Импорт данных из профилей других браузеров и выбранных файлов; настоящее отдельное экспериментальное окно WebKit.

## Вкладки и память

По умолчанию неиспользуемая вкладка остаётся в памяти **5 минут**. Обычное переключение сохраняет DOM, JavaScript и введённые данные. В меню можно выбрать таймаут 1, 5, 15 или 30 минут либо освободить память фоновых вкладок сразу.

В `preferences.json` доступны `UnloadAfterMinutes` (1–120) и `MaximumResidentTabs` (1–32, по умолчанию 8). При превышении числа резидентных страниц приложение сначала выгружает самые давно использованные фоновые вкладки. Это мягкий предел: активная вкладка, загружающаяся страница, воспроизведение звука, скачивание файла и обнаруженные изменения форм защищены от автоматической выгрузки. Проверяются `input`, `textarea` и `select`, в том числе в доступных фреймах. Страницы с `contenteditable` или недоступными фреймами сохраняются в памяти консервативно; это может относиться и к рекламным вставкам. Защита нестандартного состояния приложения остаётся эвристикой.

После выгрузки сайт загружается заново. Сохраняются адрес, название, история и снятая перед выгрузкой позиция прокрутки; прокрутка восстанавливается после загрузки. DOM/JS-состояние, несохранённые данные и результаты POST-запросов не восстанавливаются. При закрытии браузера живые страницы также завершаются; сессия хранит сведения о вкладках, а не снимки сайтов.

Запуск на пустую главную не создаёт WebView2. При восстановлении сессии загружается выбранный сайт, остальные — по требованию. При сворачивании приложение запрашивает у WebView2 режим пониженного потребления памяти.

Аниме-оформление использует один локальный исходник [assets/anime-sakura.png](assets/anime-sakura.png). Полноразмерное изображение освобождается, когда главная скрыта; для элементов интерфейса сохраняются только два небольших портрета, вырезанных из того же файла. Иллюстрация создана встроенным инструментом `image_gen`; исходное описание сохранено в [assets/anime-sakura.prompt.txt](assets/anime-sakura.prompt.txt). Для замены рисунка достаточно заменить PNG; координаты портретов находятся в `UI\AnimeArtwork.cs`.

Закладки, пароли и импорт находятся в отдельной `Feather.Features.dll`: модуль загружается при вызове функции в выгружаемый `AssemblyLoadContext`, а после операции освобождается для сборки мусора. Завершение выгрузки зависит от GC; мгновенное уменьшение рабочего набора не гарантируется. Системные библиотеки SQLite и DPAPI открываются на время соответствующей операции, их дескрипторы затем освобождаются. WebKit работает в отдельном процессе, который завершается при закрытии его окна.

Счётчик внизу показывает приблизительную сумму рабочих наборов приложения и процессов его WebView2. Общие страницы памяти могут учитываться повторно; отдельный процесс WebKit в этот счётчик не входит. Подсказка показывает private commit и число процессов. Фиксированного лимита памяти нет. Сравнительных бенчмарков с Firefox в проекте нет, превосходство по скорости или памяти не заявляется. Основная программа остаётся на C#; нативные системные API используются там, где они нужны, без недоказанного ускорения от переписывания на C++.

## Перенос закладок, паролей и cookie

Откройте меню **«Импорт из другого браузера…»**. Профили Chrome, Edge, Brave, Vivaldi, Opera / Opera GX, Chromium и Firefox ищутся в стандартных папках. Можно выбрать файл вручную. Базы Firefox открываются только для чтения. Исходные файлы не изменяются; если база занята, закройте исходный браузер и повторите действие. История другого браузера, настройки и расширения не переносятся.

| Данные | Поддерживаемый перенос |
| --- | --- |
| Закладки | Экспорт HTML; файл `Bookmarks` / JSON Chromium; Firefox — экспорт HTML или `places.sqlite`. Импортируются HTTP/HTTPS-ссылки в общий список без исходной иерархии папок. Повторяющиеся адреса пропускаются. |
| Пароли | CSV, экспортированный Chrome, Edge или Firefox, в отдельное хранилище Feather; также ручное добавление и редактирование. |
| Cookie Firefox | `cookies.sqlite` выбранного профиля, включая современные схемы 16+ с `expiry` в миллисекундах и старые схемы с секундами. Разделённые cookie сохраняют сайт верхнего уровня и признак cross-site ancestor. |
| Cookie из файлов | JSON-массив, объект с массивом `cookies` или Netscape TXT. JSON поддерживает `partitionKey` с сайтом верхнего уровня и признаком cross-site ancestor; TXT используется для обычных cookie. После импорта обновите сайт. |

**Пароли:** встроенное сохранение и автозаполнение WebView2 включены и работают отдельно от импортированных записей. Импортированные и добавленные вручную пароли хранятся в `passwords.dpapi`, зашифрованном Windows DPAPI для текущей учётной записи. Одна подходящая запись автоматически заполняет пустую форму входа при загрузке страницы или появлении формы позже. Если записей несколько, при фокусе на поле логина или пароля появляется меню выбора рядом с этим полем. Отдельное окно и сочетание клавиш для обычного заполнения не нужны; **Ctrl+Shift+L** лишь повторно вызывает подсказки.

Для импортированных паролей должны совпадать протокол, домен и порт; заполнение доступно на HTTPS и локальном сервере. Уже введённые пользователем данные автоматически не заменяются, форма не отправляется. Проверяется форма в основном документе: формы с `new-password`, несколькими полями пароля, признаками регистрации / смены пароля или отправкой на другой origin пропускаются. Перенос CSV не добавляет записи во внутренний менеджер WebView2. Исходный CSV содержит открытые пароли и автоматически не удаляется.

**Разделённые cookie:** поддерживаемый текущим WebView2 контекст переносится через CDP с исходным `partitionKey`. Записи отдельных контейнеров, приватных контекстов и first-party isolation пропускаются, сохраняя их отделение от обычных cookie. Если движок не поддерживает нужный контекст или требует отсутствующий у исходной записи `Secure`, запись также пропускается; преобразования в обычную cookie нет. Результат показывает фактически применённое число, отказы движка и причины пропуска при чтении, включая истёкший срок и неподдерживаемую изоляцию.

**Cookie Chromium:** защищённые базы Chrome/Edge и других Chromium-браузеров автоматически не расшифровываются. Встроенной кнопки экспорта cookie в них нет: нужен выбранный вами доверенный инструмент или расширение, создающее JSON или Netscape TXT. Затем выберите полученный файл в Feather. Импорт cookie может перенести авторизованные сеансы, но не гарантирует вход на каждом сайте: часть состояния может находиться в другом хранилище или быть привязана к устройству.

## WebKit

Пункт меню **«Открыть в WebKit — эксперимент»** запускает текущий HTTP/HTTPS-адрес в настоящем WebKit из `Microsoft.Playwright`, в отдельном окне и с отдельным профилем. При первом использовании предлагается скачать нужный runtime.

Это тестовая сборка движка Playwright и экспериментальный просмотр: он не заменяет движок основных вкладок, не является Safari и не объединяет с ними закладки, пароли или cookie. Установка, ограничения, поддерживаемая Windows и отдельная проверка описаны в [ENGINE.md](ENGINE.md).

## Управление

| Клавиши | Действие |
| --- | --- |
| Ctrl+L / Alt+D | Адресная строка |
| Ctrl+T | Новая вкладка |
| Ctrl+W / средняя кнопка по вкладке | Закрыть вкладку |
| Ctrl+Tab / Ctrl+Shift+Tab | Следующая / предыдущая вкладка |
| Alt+← / Alt+→ | Назад / вперёд |
| Alt+Home | Выгрузить текущий сайт и открыть главную |
| F5 / Ctrl+R | Обновить / остановить загрузку |
| Ctrl+J | Загрузки |
| Ctrl+D / Ctrl+Shift+B | Закладки |
| Ctrl+Shift+P | Хранилище паролей |
| Ctrl+Shift+L | Повторно показать подсказки сохранённых паролей |
| F11 / Escape | Полный экран / выход из полного экрана |

Поиск выполняется в Google. Адрес без схемы открывается через HTTPS, `localhost` и loopback — через HTTP. Поддерживаются HTTP/HTTPS; локальные файлы и запуск внешних приложений специальными схемами не предусмотрены.

## Профиль

Основные данные: `%LOCALAPPDATA%\FeatherBrowser\`. Одновременно запускается один основной экземпляр на пользователя.

| Путь | Содержимое |
| --- | --- |
| `session.json` | Вкладки, история и сохранённая прокрутка |
| `preferences.json`, `theme.json` | Политика выгрузки и тема |
| `bookmarks.json` | Закладки |
| `passwords.dpapi` | Отдельное зашифрованное хранилище паролей |
| `WebView2\` | Профиль основных вкладок: cookie, кеш и данные сайтов |
| `WebKitPreview\` | Отдельный профиль WebKit |
| `Engines\WebKit\` | Установленный runtime WebKit |
| `errors.log` | Диагностические ошибки |

Это обычный сохраняемый профиль: адреса и данные сайтов записываются на диск. Копирования `passwords.dpapi` на другую учётную запись недостаточно для расшифровки.

## Сборка и проверки

```powershell
dotnet build .\Feather.csproj -c Release
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\test.ps1
```

`build.ps1` публикует основное приложение, модуль библиотеки данных и отдельный помощник WebKit в `dist`. Дистрибутив framework-dependent: .NET и основной WebView2 Runtime в него не включаются. Runtime WebKit скачивается при первом запросе или вручную по инструкции в [ENGINE.md](ENGINE.md).

`test.ps1` собирает Release и запускает `--self-test` и `--smoke-test`. Проверяются разбор адресов, сессия, настройки, политика выгрузки, импорт и шифрование данных. Регрессионные проверки Firefox используют старую базу с секундами и схему 17 с миллисекундами, отдельными разделами, контейнером и cookies сеанса; исходные базы остаются неизменными.

Smoke-тест открывает настоящий WebView2 с локальным HTTP-сервером и проверяет страницы, состояние вкладок, выгрузку, восстановление, реальное хранение разделённых cookie и точность отчёта импорта. Проверки рамки воспроизводят открытие меню и смену фокуса. Проверки паролей покрывают автоматическое заполнение обычной и динамической формы входа, выбор нескольких записей во всплывающем меню и ограничения заполнения. Обычный профиль не используется: тестовые данные остаются в `%TEMP%\Feather-smoke-*`. Результаты — `smoke-results.json`, изображение главной — `preview.png`. Проверка экспериментального WebKit запускается отдельно, как описано в `ENGINE.md`.
